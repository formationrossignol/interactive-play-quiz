## Design Specificity Verdict

**LLM assessment**: Mixed. ## Overall Impression

The Material 3 register itself is well-executed where it actually renders — tonal cards, restrained color, real per-section error handling. But the surface has two problems that undercut the "trustworthy admin tool" premise the whole skin exists to serve: the numbers on the dashboard are provably wrong (8 vs 25 creations, different data sources), and the calm register isn't even guaranteed to be what a user sees, since nothing forces Material 3 on the correction/admin route tree. The biggest opportunity is fixing both at once — they're the same underlying issue: this surface behaves as if design-and-data correctness were optional for an "admin" page, when this product's whole positioning (training managers making decisions from these numbers) depends on the opposite.

## What's Working

1. **KPI-to-chart linking** (`KpiRow.tsx`'s `scrollToChart`) — clicking a KPI tile smooth-scrolls to its detail chart, a genuine recognition-over-recall touch most dashboards skip.
2. **Per-section error/retry isolation** (`DashboardSectionError` in `Dashboard.tsx`) — stats and charts fail and retry independently instead of blanking the whole page.
3. **Restrained, correctly-toned empty states** — "Pas encore de score sur les 14 derniers jours" instead of a raw dash or spinner, with `emptyHint` logic avoiding repeating identical copy across all 4 KPI tiles.

## Priority Issues

**[P0] Dashboard KPI/chart numbers come from a different, stale data source than the actual content library**
- **Why it matters**: `computeDashboardStats`/`computeDashboardCharts` (`dashboardStats.ts`) call `getUserQuizzes()` from `quizStorage.ts`, reading `localStorage.getItem('saved_quizzes')`, while `/my-quizzes` reads from a separate content store via `contentRepo.ts`. Live-verified: dashboard showed "8 Créations" while My Quizzes showed 25. This is the landing page of an analytics product training managers use to gauge program activity — the number is wrong, and wrong silently, with no discrepancy indicator anywhere (heuristics #2, #9).
- **Fix**: Point `dashboardStats.ts` at the same content source `contentRepo.ts` uses, or add a consistency check; add a test asserting `computeDashboardStats(userId).totalCreations` matches `listContent` counts.
- **Suggested command**: `/impeccable harden`

**[P1] Material 3 is not enforced as the default on correction/admin routes, contradicting DESIGN.md**
- **Why it matters**: Theming is a single global `<html data-theme>` toggle (`siteTheme.ts`, `DEFAULT_SITE_THEME = "arcade"`) with no per-route override. DESIGN.md states Material 3 "should never borrow Arcade Pop's vocabulary" on correction/admin surfaces, and PRODUCT.md names the playful-vs-calm register split as Product Principle #1. Empirically confirmed: a default-theme session on `/dashboard` and `/grading` showed bounce-easing, pulsing-dot, side-tab, marquee, and dark-glow — exactly the vocabulary the design system forbids there.
- **Fix**: Scope the correction/admin route tree to always render `data-theme="material"` regardless of the user's site-theme picker choice, or explicitly revise DESIGN.md to acknowledge the picker overrides it.
- **Suggested command**: `/impeccable harden`

**[P1] Exam grading queue has no dedicated workspace and buries a core workflow**
- **Why it matters**: The sidebar's "Correction" group only contains "Saisie des notes" (manual offline grading) and "Mes notes" — exam submissions are reachable only via dashboard banner → `/notifications` → individual notification → deep link, with a full-page reload (`window.location.href`, not `navigate()`) on every hop. Clearing 3 pending submissions takes 4+ clicks and 3 reloads. `/my-quizzes` also skips a heading level (`<h1>` directly to `<h3>`, no `<h2>`), adding a screen-reader navigation gap on the same content-browsing path.
- **Fix**: Add a first-class "Copies à examiner" nav item or badge that lists pending exam submissions directly; fix notification click to use `navigate()`; restore the missing `<h2>` on `/my-quizzes`.
- **Suggested command**: `/impeccable layout`

**[P2] Design-token drift at scale — 847 deterministic findings against DESIGN.md's documented ramps**
- **Why it matters**: 422 undocumented colors and 338 off-ramp font sizes, concentrated in `QuizSession.tsx`, `ExamAdmin.tsx`, and the legacy theme CSS files (`theme-thales.css`, `theme-innov.css`, `admin.css`, `community-pages.css`), plus 24 bounce/elastic-easing instances and 13 layout-property transitions (`width`/`margin`, which are expensive to animate). At this scale, DESIGN.md's tonal system reads as aspirational for large parts of the app rather than enforced.
- **Fix**: Run a token-extraction pass on the highest-concentration files first (`QuizSession.tsx`, `ExamAdmin.tsx`), then the legacy theme CSS files; swap `transition: width/margin` for `transform`-based equivalents.
- **Suggested command**: `/impeccable extract`

**[P2] Accessibility and i18n consistency gaps**
- **Why it matters**: Trend-badge text (`TrendBadge` in `KpiRow.tsx`) uses `#15c08a`/`#ff5a4d` on `surface-container-low`, computing to ~2.35:1 and ~3.08:1 contrast — both fail WCAG AA's 4.5:1 for normal text, on exactly the numbers ("+12%", "-8%") a training manager needs to read at a glance. Separately, the sidebar's collapse control (`sidebar.tsx`) has a hardcoded English `aria-label="Toggle Sidebar"` in a product PRODUCT.md calls "French-first... durable, not incidental."
- **Fix**: Darken both trend colors to pass 4.5:1 against the card surface tone; translate the sidebar trigger's aria-label and sr-only text to French.
- **Suggested command**: `/impeccable audit`

## Persona Red Flags

**Alex (Power User)**: No keyboard shortcut or bulk-select anywhere on the grading path — the global ⌘K palette doesn't surface "jump to grading queue" or "grade next submission." The KPI numbers Alex would glance at first are wrong (P0) — the fastest path in the product gives the least trustworthy data. Clearing a 3-item grading queue takes 4+ clicks and 3 full-page reloads.

**Sam (Accessibility-Dependent)**: Sidebar collapse control's `aria-label="Toggle Sidebar"` is hardcoded English in a French-first product — a French screen-reader user hears an English label on primary chrome. Trend-badge red/green text fails AA contrast (~2.35:1/~3.08:1 vs required 4.5:1) — a low-vision user reading the percentage text itself, not just the color, still can't reliably read it. `/my-quizzes` skips from `<h1>` to `<h3>` with no `<h2>`, breaking screen-reader heading navigation. On the positive side: tabbing to "Lancer une session" showed a clear, high-contrast violet focus ring — that part works.
